# 本郷ワークロード600リクエスト延長実験：TTFT安定性の検証

## 目的

従来の300リクエスト実験では、観測時間が短いため、到着率が処理能力をわずかに上回っていても遅延蓄積を見落とす可能性がある。そこでPeak 1x〜5xのワークロードを600リクエストへ延長し、前半300件と後半300件のTTFTを比較した。

この実験でいう「安定」とは、リクエスト数を増やしても未処理仕事量が継続的に増えず、後半のTTFTと待ち時間が前半より系統的に悪化しない状態を指す。

## 実験条件

- 元の300件を同じ到着間隔・リクエスト構成のまま2回連結した。
- 2周期目のrequest ID、session ID、token IDには別namespaceを与え、周期をまたぐ意図しないprefix cache hitを防いだ。
- 1周期目終了時にシステム状態はリセットしない。したがって、処理し切れなかった待ち行列は2周期目へ引き継がれる。
- 各ワークロードについて次の4方式を比較した。
  1. `no_redirect`: リダイレクトなし
  2. `redirect_no_kv`: リダイレクトあり、KV migrateなし
  3. `redirect_kv_nopp`: KV migrateあり、PP1
  4. `redirect_kv_pp2`: KV migrateあり、PP2
- TTFTは`e2e_ttft_ns`を使用した。
- Peak 1x〜4xは16実験を最大4並列で実行し、全CSVが600件を含むこととエラーがないことを確認した。Peak 5xは先行して同じ条件で実行した。

## 発見

### Peak 1xは安定域

約9 RPSでは全方式の前半・後半差が約3%に収まった。150件ずつに分けた方式1の平均TTFTも`287.2 → 254.2 → 302.4 → 256.1 ms`であり、時間に対する単調増加ではない。方式1のTTFT前待ち時間も前半26.8 ms、後半29.9 msに留まった。この差は遅延蓄積より、周期内のリクエスト構成と短期的な混雑の揺らぎとして解釈するのが妥当である。

### 遅延蓄積はPeak 2xから観測される

約18 RPSでは全方式で後半TTFTが増加した。方式1ではTTFT前待ち時間が373.8 msから2953.0 msへ、方式2では54.5 msから957.3 msへ増えており、平均TTFT悪化の中心は待ち行列の蓄積である。

方式4は最も悪化を抑え、平均TTFTを312.9 msから365.2 ms、TTFT前待ち時間を33.1 msから42.7 msの増加に留めた。しかし後半TTFTは16.7%増えているため、少なくとも「10%以内」を安定条件にする場合、Peak 2xを安全域とは判定できない。

### Peak 3x以上は全方式で明確な過負荷

約27 RPS以上では、後半TTFTが前半の約4.8〜11倍になった。PP2もTTFTを相対的に改善するが、増加傾向そのものは止められていない。高負荷域におけるPP2の効果は、安定化ではなく遅延蓄積速度の緩和と解釈すべきである。

### 300件の全体平均だけでは安全上限を過大評価しうる

Peak 2x・方式4は最初の300件では平均312.9 msと良好に見えるが、同じ負荷を継続すると後半は365.2 msへ上昇する。他方式では差がさらに大きい。短い観測窓の平均TTFTだけでは、初期の空状態による低遅延を含むため、定常的に処理可能な到着率かどうかを判断できない。

## 現時点での安全上限

今回測定した離散点からは、次のように整理できる。

- 約9 RPS: 安定域
- 約18 RPS: 境界を越えている、または少なくとも境界域
- 約27 RPS以上: 明確な不安定域
- 本郷ワークロードの安全上限: 約9〜18 RPSの間

方式4は他方式より安全上限が高い可能性があるが、18.067 RPSでも後半が16.7%悪化したため、安全上限が18 RPS以上であるとは言えない。

## 判定方法に関する示唆

前半・後半差だけを固定閾値で判定するのではなく、次の指標を組み合わせるべきである。

1. 前半300件と後半300件の平均・p95 TTFT差
2. 150件程度の複数区間に分けたTTFTの傾き
3. router待ち時間とscheduler待ち時間の傾き
4. 実験終了時の未処理仕事量または待ち行列長
5. 同じ条件を複数seedで実行したときの再現性

1%の差が直ちに発散を意味するわけではない。有限区間の構成差や一時的な揺らぎでも差は生じる。重要なのは、区間を延ばしたときにTTFTと待ち時間が単調かつ継続的に増えるかである。

## 次の検証

安全上限を絞り込むには、Peak 1xと2xの間を追加測定する。

| 倍率 | おおよそのRPS |
|---|---:|
| Peak 1.25x | 11.3 |
| Peak 1.5x | 13.5 |
| Peak 1.75x | 15.8 |

各点を最低600件、可能なら1200件および複数seedで実行し、特に方式4のTTFTと待ち時間の傾きを確認する。
