# Hongo 1x–10x: 遅延・電力量トレードオフ分析

## 結論

今回の PP=2、各負荷 300 リクエスト、3 構成 × 10 負荷の比較では、東京・鹿児島への分散配置は、全東京配置に対して推定電力量をほぼ増やさず、推定電気料金を平均 18.5% 削減した。一方、平均 TTFT は 0.27–2.15% 増加した。地理分散による通信時間の増分は平均約 5.25 ms であり、高負荷時には待ち時間が支配的になるため、相対的な遅延ペナルティは小さくなる。

負荷を上げると、300 件を処理する観測時間が短縮されるため、推定電力量は 1x の約 70.1 Wh から 8–10x の約 45.1 Wh まで減少する。ただし平均 TTFT は 264.6 ms から 1913.5 ms へ増加する。電力削減の大半は 1x から 4x までで得られ、4x 以降は電力量の改善が小さいのに遅延が急増する。遅延と電力量の折衷点としては 3x–4x が妥当である。

提案方式は全負荷で redirect 0 件、prewarm hit 0 件だった。3x 以降では各負荷 2 件の wasted prewarm があり、鹿児島 baseline に対する効果は平均 TTFT で最大 0.20%、p95 で最大 2.70% の改善に留まる。したがって、この PP=2 条件では提案機構が本来想定した経路変更・KV 再利用を発動できていない。

- 推定電力量: +0.002–0.044%、実質同等
- 推定電気料金: −17.26–−18.73%、10負荷平均 −18.49%

## 負荷と遅延の関係

全東京 baseline の平均 TTFT 内訳を見ると、1x では prefill service が 243.4 ms、queueing が 19.9 ms だった。10x では prefill service が 526.4 ms、queueing が 1385.8 ms となる。高負荷での TTFT 悪化は主として queueing の増大による。

- 1x → 4x: 電力量 70.13 → 47.96 Wh（−31.6%）、平均 TTFT 264.6 → 525.3 ms（+98.5%）
- 4x → 7x: 電力量 47.96 → 45.29 Wh（−5.6%）、平均 TTFT 525.3 → 1285.2 ms（+144.7%）
- 7x → 10x: 電力量 45.29 → 45.17 Wh（−0.3%）、平均 TTFT 1285.2 → 1913.5 ms（+48.9%）

したがって、電力量だけを優先するなら 8x 付近で下限に達するが、遅延とのバランスでは 3x–4x より高い負荷に上げる利点は小さい。SLO が平均 TTFT 500 ms 前後なら 3x、約 550 ms を許容できるなら 4x が候補になる。

## 提案方式の評価

提案方式と東京+鹿児島 baseline は大半の負荷で同一か、ほぼ同一だった。

- redirect: 全負荷で 0 件
- proactive prewarm hit: 全負荷で 0 件
- wasted prewarm: 1x–2x は 0 件、3x–10x は各 2 件
- 最大の平均 TTFT 改善: 4x の −0.20%
- 最大の p95 TTFT 改善: 10x の −2.70%
- 電力量差: 最大でも約 0.04 Wh

9x–10x の p95 改善は見えるが、hit が 0 件なので、提案方式の狙いどおりの KV prewarm 成功による結果とは解釈できない。発動条件、PP=2 の配置・容量判定、Hongo PP=1 実験との差を次に追う必要がある。

## 電力推計の前提と制約

電力モデルは既存の rate-4 分析と同じで、GPU 利用率 0% を 50 W、100% を 450 W とする線形モデルである。料金単価は東京 23.0 円/kWh、鹿児島 14.7 円/kWh とした。

PP=2 の利用率 CSV は GPU ID 0–5 に処理を記録し、6–11 は 0% としている。このため、そのまま積分した値は後段GPUの動作電力を含まない。本レポートでは、ID 0–5 を論理インスタンスとみなし、その利用率を各2段へ複製して12 GPU分を推計した。分散配置では論理インスタンス 0–2 を東京、3–5 を鹿児島として料金を計算した。これは両 pipeline stage の利用率が同程度という仮定に基づくため、絶対値ではなく構成間の相対比較を主に見るべきである。
